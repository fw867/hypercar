# mDNS 与邀请连接诊断

目标：保留现有配对，为下次二次上车记录可见的服务发现与邀请连接过程。

采用现有车机 Network 上的被动 UDP 多播监听，以及现有 ctrl TCP 服务内的阶段日志。仅增加 NSD 回调日志无法确认线上查询，VPN/主动探测会改变现场；因此选择被动监听。普通应用不能据此观察 TCP SYN、旧端口流量或保证接收 NSD 的单播响应，导出日志须明确该边界。

实现：独立纯 Kotlin DNS 摘要解析器（压缩名、PTR/SRV/TXT/A/AAAA、TTL/QU/flush），仅记录发现元数据，TXT只允许id/srcvers。独立Android IPv4/IPv6被动监听器，绑定车机网络和接口，日志限速且保留计数，随网络切换/停止关闭。CarPlayCtrlAdvertiser记录NSD代次、实际实例名、网络地址、TCP accept、HTTP头完成/EOF/超时、邀请门禁和200回应；等待期每15秒快照。保留广播、门禁、握手及网络选择语义。
