# 方向盘媒体键链路补齐

依据 `hypercar-log-20261107-175436.txt`，车机曾发出单字节 `04`、`00` HID 报告。旧实现只把末字节 B5/B6/CD 当媒体键，并且 Rust `key_rx` 无消费者，因此既不能按描述符识别数组/位图，也没有通往播放器的回调。

## 实现

从会话内 `/info` 的 hidDevices（兼容 hids/hid）读取设备 UUID 与 HID 描述符，按设备、Report ID 及 Input 位偏移解析 Consumer 页。区分 Array 的逻辑值索引和 Variable 字段，支持 Usage 范围、常量补齐、Report ID、全局 Push/Pop；限制描述符大小、字段尺寸及计数，非法或截断报告不产生按键。

按设备和 Report ID 保存按下集合，只在新按下沿发送 Usage。重复按下不重复切歌，松开清除状态；与触摸使用不同解析状态。没有描述符时，仅兼容明确的直接 Usage ID，不将 04 固定猜作下一曲。未知短报告会有限记录，需车机重新测试确认具体描述符。

媒体键接收任务纳入 EngineTasks，随会话关闭取消。Usage 经 JNI `onMediaKey` 进入 MusicBridge 主线程，优先向选定 MediaController 派发一组 DOWN/UP；没有可用会话、拒绝或异常时，回退 AudioManager 的系统媒体键路由。CarWith 和自绘 UI 均使用公共流程，不依赖界面上的音乐卡片是否可见。

支持播放、暂停、播放/暂停、上一曲、下一曲、停止及基础快进/快退键。主动恢复播放、播放中的切歌操作还会触发已有音频资源申请；不由音频数据自动抢占资源。长按不实现连续快进/快退或自动重复切歌。

## 验证及限制

原生测试覆盖 Array / Bitmap、常量补齐、Report ID 与位偏移、UUID 隔离、按下/松开去重、直接 Usage 回退、范围与逻辑最小值、畸形描述符和短包。原有触摸缩放测试保留。Kotlin 测试覆盖 Usage 映射、选定会话避免双重派发、失败时系统回退及未知报告不派发。

新增 `HID-KEY`（描述符注册、未识别报告、按下 Usage）及 `MEDIA-KEY`（Android 键码、路由、目标播放器）日志。派发成功不代表音乐 App 已执行；所选播放器是否支持对应控制仍需实测。

本次没有接入方向盘语音键、语音助手唤醒、麦克风上行或语音会话资源协商，不能据此宣称语音助手可用。也不能仅凭历史 04 报告确认它在该用户车机上代表哪一个键，需要新会话描述符与按键日志验证。

构建验证：228 项 Kotlin 测试通过；Android 真机原生测试 95 项通过、0 失败、1 原有测试忽略；Lint 0 错误（47 Warning、2 Information）。完整 Rust release 与 APK 构建通过，包内原生库与本次产物 SHA256 一致。0.1.0.567 / 10567 已安装启动；该用户车机的方向盘切歌仍需实测确认。
