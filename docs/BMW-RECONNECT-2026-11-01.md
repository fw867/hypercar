## 今天提交的实际作用与缺口

### a48b0ae：HFP/A2DP 回连拦截

- BMW 档案开启 `dropProfilesBeforeIap2`，保留被动 iAP2，不开启主动 RFCOMM 连接。
- `startStandbyListening` 会启动 guard；手动连接路径本身不会启动。待连接期间开启自动连接保留手动会话，也没有补启 guard。这与下午首次 `BT-GUARD` 直到失败进入待机才出现一致。
- ACL 处理入口先检查 `autoConnect`，因此不能覆盖关闭自动连接时的手动连接。
- `CarProfileGuard` 动态接收器使用 `RECEIVER_NOT_EXPORTED`。Android 官方说明蓝牙广播可能由非 system UID 的高权限应用发送，需要 `RECEIVER_EXPORTED` 才能完整接收。当前手机蓝牙进程为 UID 1002。这是接收器覆盖问题，尚无证据证明它导致了本次失败。
- 因此下午样本既不能证明拦截已修复二次连接，也不能证明首次 7 秒中断是 guard 引起：中断前它尚未启动。

参考：https://developer.android.com/develop/background-work/background-tasks/broadcasts

### 3623b3a：待机通知开关

### 已确认的 Wi-Fi 时序缺口

`HyperCarRepo.awaitUsableEndpoint` 仅在进入函数时尝试已知 Wi-Fi 绑定及 ctrl 广播。若手动连接启动早于车机 Wi-Fi 出现，等待循环不会再执行这段恢复逻辑。

BMW 的 `requireAirplayActivation=true` 跳过了循环中的网关探测分支；同时 `queueWifiReconnectCheck` 遇到 `hasCurrentSession` 直接返回。于是等待中的手动连接收不到后到网络的恢复处理，只能等本轮 300 秒结束再重试。下午 17:53:09 → 17:58:09 的日志直接体现这一问题。

这是独立于蓝牙唤醒的问题。17:58 广播恢复后仍等至 17:59:37 车机才连入，因此仅修复五分钟延迟不能保证完全解决二次上车。

## 连接后 7 秒中断的边界

17:59:46 附近系统出现 Wi-Fi score breach、无互联网提示，17:59:47 时 Wi-Fi 仍显示 COMPLETED、RSSI 约 -42 dBm。随后应用先报本地 socket abort，约 192 ms 后才出现蓝牙断开。

这提示需要继续核查手机网络可用性判断、网络切换及 socket 绑定；现有证据不能证明是 Wi-Fi 物理断开、系统切网或车机主动停止 AirPlay。不能仅依据较晚的 HCI 0x13 将它当作蓝牙先断导致投屏断开。

## 后续修复优先级

1. 等待端点期间及时处理后来出现的已配对车机 Wi-Fi，恢复绑定和 ctrl 广播；保持“收到本轮邀请或明确 iAP2 端点后才建立 AirPlay”的约束。
2. 补齐既有 guard 的手动/自动连接生命周期及广播接收方式；尊重目标车机档案，并处理停止后的排队任务，避免扩大干预范围。其根因假设仍需实机验证。
3. 记录扫描模式变化、ACL 连接方向和网络变更时间，验证无需打开设置也能触发车机主动连入的条件。不要由单次相关性直接改为永久可发现或反复强制断开音频 profile。

验收应覆盖：上车前先点手动连接、Wi-Fi 后到；自动待机二次上车；不打开手机设置/不让车机重新搜索；建立后持续推流。上午与下午已有样本不能代替这些实车验证。

## 已完成的代码修复

- 将已配对车机网络的恢复绑定、网络监听及 ctrl 广播提取为同一入口；进入端点等待时调用，后续每次等待 tick 超时（标称 5 秒）继续检查。Wi-Fi 后到不再必须等待整轮 300 秒。相同网络不重复绑定/强制重注册，广播注册失败可在后续检查重试。
- 保留 BMW 必须收到本轮 ctrl 邀请或 iAP2 明确端点后才建立 AirPlay 的限制，没有恢复记忆端口预连或网段扫描。
- guard 是否运行由车机档案、自动待机和当前会话共同决定。手动连接也启用，连接期间切换自动模式不会漏启；档案不要求断音频 profile 时不启用。
- guard 接收器改为 `RECEIVER_EXPORTED`，仅订阅系统保护的 HFP/A2DP、ACL 广播并校验目标；增加独立的经典 ACL 入口，覆盖关闭自动模式时的手动会话。ACL 立即检查与 +4 秒检查统一由 guard 执行。
- 清理会话/切换目标时停止 guard，清除延迟回调，通过 generation 校验取消过期排队任务；获取系统 profile 代理后再次检查状态。
- 删除 guard 无条件设置的 self-drop 标记：由 `BtProfiles.disconnect` 仅在确有音频 profile 要断开时设置，空操作不会延长忽略 ACL 断开的宽限期。
- 本机 `:app:testDebugUnitTest :app:assembleDebug` 通过，65 个测试、0 失败、0 错误；新增手动会话、自动待机、档案禁用的策略覆盖。`git diff --check` 通过。没有进行实车复测，也没有将 Debug 包覆盖到手机的正式签名安装。

这些修复消除了已确认的应用流程缺口，尚不能证明无需设置页面就能令车机主动连入；连接后 socket abort 的根因也仍待实车与网络日志验证。

- [BMW issue #27](https://github.com/rPlayAI/carcast-public/issues/27) 的维护者回复将该报告的周期性掉线归于 iPhone 原生 CarPlay 与 CAR# 竞争，并提到真实蓝牙身份、车机选中手机及 build 13 的调整。这是该项目特定问题的解释，不能直接当作 HyperCar 下午 socket abort 的根因，也没有公开可移植实现。
