# 视频、触摸与画面资源

更新：2026-11-07。音频独立见[AUDIO](AUDIO.md)。

## 尺寸与配置

优先 /info 的 widthPixels/heightPixels，兼容旧 width/height；缺少有效数据时使用设置兜底（默认1920×1080）。自绘编码沿用实际画布、偶数对齐和用户帧率，不固定所有宝马为2732×794。viewAreas/安全区域用于布局和同源坐标换算，不直接缩小整幅画布。

CarWith 实际画布受其本机编码器和2560×2560边界约束。VideoConfig 优先 SPS 可见尺寸，源实际尺寸与触摸空间保持对应；不能仅改头部尺寸宣称真实画面已拉伸。旧 carwith_stretch 偏好不覆盖实际编码尺寸。

来源 AU、向 socket 写出的帧、TCP ACK 和车机解码显示不是同一层。config / IDR 日志保留源尺寸、SPS、头部尺寸及实际写出证据，屏幕 opcode 保活不算视频帧。

## 流切换与归属

首帧等待正确配置和 IDR；源重建清除旧轮配置及片段，不把上一轮的 SPS/PPS 当成本轮成功。地图卡片/全屏复用任务，切换编码器和 Surface，避免两个画面源持续争抢。

画面资源联动由用户实验开关或车型字段 useScreenResourceLifecycle 启用（OR，不改用户保存值）；奔驰试验档案强制开启，其它档案保持默认。取得屏幕资源后声明并 SETUP；收回时暂停并释放屏幕流，保留控制、iAP2及音频。等待后重查资源版本，禁止旧回调重装失效端点。屏幕 SETUP 400 时可以保留控制等待后续资源变化，但这不表示400已解决。

已删除的“CarPlay界面恢复”和“视频通道重建”两项旧实验不再提供设置或执行分支，历史过程从 Git 查询。当前画面资源联动不是把旧实验重新启用。

## 诊断与边界

PIPELINE 分开显示 RECORD、资源、screen_setup、video_tcp_ready、源数量及已写帧。SETUP 和资源请求记录 CSeq、完整出站 plist/hex/哈希及 RTSP/业务应答。空体400只能证明请求被拒，EOF不能反推拒绝码。旧 TCP 端点一旦失效，先使输出和触摸所有者失效，再关闭 socket；连接号和采样年龄用于避免把旧连接统计当成本轮状态。

保留目前已验证的 nonce、AAD、HKDF及NTP映射；没有证据时不因为别的接收器参数不同就改宝马加密和帧头。测试边界见[验证](VALIDATION.md)，协议见[PROTOCOL](PROTOCOL.md)。
