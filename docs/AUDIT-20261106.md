### 可以定位到哪里，仍缺什么

本次可将无邀请路径定位为：真实 TCP 连接成功 → pair-verify 通过 → auth-setup 200 → 会话 SETUP 200 → /info 2736×800 → RECORD 200 → 初始 modesChanged 的 POST /command 等待中 EOF。尚未到屏幕 SETUP、视频 TCP、编码器首帧，所以这几轮不宜优先归咎 CarWith 启动、SPS/PPS/IDR 或视频 socket 路由。

EOF 没有 RTSP 业务拒绝码；发生在等待 POST /command 时不证明车机读取并解析该报文后才关闭，也可能是 RECORD 后的延迟关闭。无法仅凭本日志确认是激活上下文缺失、资源字段不匹配，还是另一条车机内部状态变化。已有邀请的前三轮后续仍断开，也表明邀请是本段资源阶段通过的强关联，不能等同于整个投屏稳定性的充分条件。
