# 会话控制与自动连接

更新：2026-11-07。当前机制不构成二次上车成功率保证；真实媒体结果见[验证](VALIDATION.md)。

## 首次使用与待机

按权限、画面来源、配对顺序引导。StartupRequirements统一读取运行时权限、系统开关与来源依赖；自绘UI必须安装/运行/授权Shizuku，CarWith必须检测到已启用的com.miui.carlink。启动与自动连接入口使用同一就绪条件，来源变化后重新核实，不用旧的授权结果代替检查。

自动模式把持久待机身份与单轮会话分开。目标MAC是车机身份边界，同名Wi-Fi不能共用配对身份。已授权的系统配对、长期AirPlay身份和临时端点各自管理，不因每次失败就全部清空。

## 发现和蓝牙

主监听使用cafe服务，附加CarPlay Phone标记UUID为2d8d2466-e14d-451c-88bc-7301abea291a，动态RFCOMM通道复用过滤及会话处理。主服务优先、附加服务独立重试，开关不影响主监听；注册了SDP/EIR不等于车机已接受标记或实车重连改善。

增强发现只在已有系统配对设备中做定向SDP，不配对或连接陌生设备；经典可发现窗口有界、按目标与当前占用限制，并在开始连接、停止或超时时清理。worker发布socket和Wi-Fi handoff使用同一门控，旧代次回调不能迟到接管。

BMW默认不主动拨iAP2、不主动断HFP/A2DP。其它档案依赖自身策略，不把“蓝牙已连接”一律当作要拆ACL的理由；音频配置保护不能拆掉正在承载业务的RFCOMM。

## 主动Wi-Fi与邀请

正常邀请和当前iAP2端点优先。启用主动开关、车型允许、配对身份/目标匹配且Wi-Fi已绑定时，网络稳定至少10秒后可尝试。端口可连接不证明车机已激活。

控制连接或视频TCP前失败时，只回收失败引擎。连接失败及其它暂态失败按10/20/40/60秒退避，之后至少60秒间隔；范围绑定Network和车机MAC。若无邀请的主动连接已获RECORD确认、却在初始资源确认前结束，则本轮同一车机/网络只等待新邀请，不定时重放同一激活；新连接轮次或新网络仍可作首次主动尝试。这是按阶段收敛恢复，不代表收到明确拒绝码。

媒体失败可暂用同范围仍可连接候选，控制端口失效则清除后重新发现。真实邀请或新iAP2端点可提前继续。未配对网络、开关关闭、车型禁用或其它车机占用时仍只等待邀请。

555–557“首次失败后整轮只等邀请”已被后续有界重试替代。大众仍要求当前网络20秒内ctrl邀请，奔驰禁用无本轮参数的主动捷径；这些不施加给BMW。详情见[档案](HEADUNIT-PROFILES.md)。

## 停止、清除与退出

手动停止取消本轮并保留至少10分钟自动连接休眠；不能由后续ACL/Wi-Fi事件立即绕过，允许手动重新开始。自动关闭时释放监听及发现资源；自动待机可保留身份声明但不扫描、不拨号、不执行iAP2握手。

单车清除按明确MAC处理配对/凭据；全部清除是另一个高级操作。停止与系统解绑、删除身份不能混为一谈。媒体任务、网络租约、端点及UI生命周期按会话代次回收；正常退出先停媒体，再有界TEARDOWN，异常退出不伪造优雅成功，见[协议](PROTOCOL.md)。

## 设置与状态

首页自动连接快捷开关与设置使用同一持久值；会话连接时显示阶段卡片。深浅主题/跟随系统仅改变手机App，车机主题在车机设置。连接诊断见[阶段说明](HANDSHAKE-DIAGNOSTICS.md)。
