# 手动会话与自动模式（0.1.0.403）

“上车自动连接”只控制后台待机监听、车机触发连接和会话结束后的自动重连。
首页的启动/停止属于手动控制，在两种自动模式下均可使用。

| 当前状态 / 操作 | 自动模式关闭 | 自动模式开启 |
|---|---|---|
| 待机 | 不持续监听；可手动启动 | 保持 iAP2 监听，首页仍为待机 |
| 手动启动 | 创建当前会话与其必要监听/保活 | 创建当前会话，复用已存在的监听 |
| 手动停止 | 结束当前会话，停止监听、重连和会话前台服务 | 只结束当前会话，保留监听、自动重连与待机前台服务 |
| 连接中切换自动模式 | 保留当前会话，仅禁用后续自动行为 | 保留当前会话，允许后续自动行为 |
| 待机时切换自动模式 | 立即停止监听和待机前台服务 | 只启动监听，不以“正在连接”占用首页状态 |

实现边界：

- `AutomaticConnectionPolicy` 描述决策，手动入口不会被自动开关拒绝。
- Repo 使用同一互斥锁串行化手动启动/停止与自动模式切换。
- 待机协调器收到车机端点后才触发自动会话；端点在交接期间缓存，避免丢失热点凭据。
- 会话复用现有协调器，手动停止且自动模式开启时只结束其当前 RFCOMM 通道，保留 accept 监听。
- 切换车机档案在下一轮使用新协调器；清除旧目标端点缓存。
- 当前会话的前台保活与自动待机保活区分：待机通知为“正在监听车机，等待自动连接”，
  不持 CPU / WiFi 锁；手动会话即使自动模式关闭，也可拥有自己的前台保活。
- 自动重连继续受已成功建立过链路、退避次数等原有规则约束；保留自动能力不等于强制立刻重连。
- 不退出应用进程，不修改系统蓝牙开关或其它 App 的 BLE 连接。

验证：新增决策矩阵测试 4 项，加上原有测试共 31 项通过。
USB 实机确认：自动关闭时可手动进入 iAP2 协商；协商中开/关自动模式均保留会话；
自动关闭时手动停止会关闭监听；自动开启时手动停止后监听仍运行，首页回到待机。
