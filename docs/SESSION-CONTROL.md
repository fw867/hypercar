# 会话控制

更新：2026-11-02。以下是当前机制，不构成二次上车成功率保证。

## 首次与待机

首次需要在车机侧把手机选为 Apple CarPlay 设备并确认配对。手机加入 Wi-Fi、系统显示已配对、本地服务已注册，均不能单独证明车机已经激活本轮 CarPlay。

“上车自动连接”启用时保持待机监听；目标车机经典蓝牙 ACL、已知车机 Wi-Fi 和增强发现可唤醒或恢复待机。ACL 接收器忽略非目标以及 LE 链接，避免把数字钥匙链路当作 CarPlay。手动连接在自动模式开关两种状态下均可使用。

内置宝马档案要求车机本轮控制邀请或当前 iAP2 提供可用端点后才建立 AirPlay；远程档案覆盖会影响这一门槛，见[档案解析边界](HEADUNIT-PROFILES.md)。不能把主动探测旧端口当成车机已激活的证据。

## 增强发现与短时可发现

在设置的目标车机列表点击车机，系统批准 CompanionDeviceManager 关联后，在配对时间旁显示“增强发现”标签。关联不代替蓝牙配对；只在自动连接开启时观察目标。切换目标会解除旧关联，关闭自动连接会停止观察。授权请求和成功处理使用去重机制。

“蓝牙回连唤醒”默认开启：已知的已配对车机 Wi-Fi、主监听和控制服务注册就绪后，等待 5 秒仍未开始新连接时，每轮尝试一次最多 30 秒的经典可发现窗口。需要 Shizuku。开始连接、停止或超时后清理。独立 watchdog 处理超时与父进程退出；HyperOS 实测不能只依赖 discoverable timeout 自动退出。

## CarPlay 蓝牙标记服务

“CarPlay 蓝牙身份广播”默认开启，在主 iAP2 服务之外注册安全 RFCOMM 服务：

- 名称：`CarPlay Phone`。
- UUID：`2d8d2466-e14d-451c-88bc-7301abea291a`。
- 使用系统动态分配的 RFCOMM 通道，复用目标过滤和会话处理，已有会话时不能抢占。
- 主服务优先启动，附加服务独立重试；开关只控制附加服务。

Android 通过服务注册管理 SDP/EIR。这不是直接调用 Linux 的原始 HCI add_uuid。当前没有新版本车端抓包证明标记已被车机接收，也没有实车证据证明它改善了二次上车。

## 音频蓝牙配置文件保护

当前内置宝马档案启用配置文件保护；远程档案可覆盖该值。仅在档案允许且自动模式或当前会话存在时，对目标车机实际已连接的 HEADSET、A2DP、LE_AUDIO 尝试断开。按监听代次过滤并节流，不调用设备级 disconnect，也不因仅处于 connecting 状态就断开。

该策略是当前兼容性实现；其对宝马重连的收益尚未证实。日志“断开 无”表示没有实际断开配置文件，不能解释为主动拆掉 ACL。

## 停止

用户停止走有界的优雅关闭：先停媒体，再尽力发送已建立流的 RTSP TEARDOWN，关闭控制连接，等待核心退出，最后清理旧蓝牙会话和网络绑定。网络丢失等故障走强制关闭。蓝牙切换到 Wi-Fi 不属于整轮退出。

自动模式下手动停止仍保留待机，后续事件可再次触发连接；自动模式关闭时完整释放。协议边界见[协议](PROTOCOL.md)，实测边界见[验证记录](VALIDATION.md)。
