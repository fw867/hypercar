# 会话控制与自动连接

更新：2026-11-14。当前机制不构成二次上车成功率保证；真实媒体结果见[验证](VALIDATION.md)。

## 首次使用与待机

按权限、画面来源、配对顺序引导。StartupRequirements统一读取运行时权限、系统开关与来源依赖；自绘UI必须安装/运行/授权Shizuku，CarWith必须检测到已启用的com.miui.carlink。启动与自动连接入口使用同一就绪条件，来源变化后重新核实，不用旧的授权结果代替检查。

自动模式把持久待机身份与单轮会话分开。目标MAC是车机身份边界，同名Wi-Fi不能共用配对身份。已授权的系统配对、长期AirPlay身份和临时端点各自管理，不因每次失败就全部清空。

## 发现和蓝牙

主监听使用cafe服务，附加CarPlay Phone标记UUID为2d8d2466-e14d-451c-88bc-7301abea291a，动态RFCOMM通道复用过滤及会话处理。主服务优先、附加服务独立重试，开关不影响主监听；注册了SDP/EIR不等于车机已接受标记或实车重连改善。

增强发现只在已有系统配对设备中做定向SDP，不配对或连接陌生设备；经典可发现窗口有界、按目标与当前占用限制，并在开始连接、停止或超时时清理。worker发布socket和Wi-Fi handoff使用同一门控，旧代次回调不能迟到接管。

BMW默认不主动拨iAP2、不主动断HFP/A2DP。其它档案依赖自身策略，不把“蓝牙已连接”一律当作要拆ACL的理由；音频配置保护不能拆掉正在承载业务的RFCOMM。

已配对宝马二次上车常见顺序：手机先自动连上车机 Wi-Fi，经典蓝牙只出现短暂 ACL 窗口随后退场，会话应走 Wi-Fi 上的 `_carplay-ctrl._tcp` 邀请；`accepted=0` 或 ACL 很快断开本身不等于失败。不要把持续蓝牙 iAP2 会话当成二次上车前提。这台 MGU 的实车前提是：ctrl 已经在广播时，邀请仍要等车机自己打开经典 iAP2，打开之后才到；短 ACL 退场不表示邀请已经在路上。

## 主动Wi-Fi与邀请

目前有两个独立开关，默认均关闭，新开关不复用旧保存值：

- **已配对车机 Wi-Fi 主动连接（实验）**：恢复中断恢复限制之前的路径。只在已配对车机、凭据与已知热点归属匹配、当前绑定 Network 有效且无其它车机占用时，稳定约10秒后主动尝试 AirPlay / Wi-Fi iAP2，不要求本进程先观察到正常连接再断开。失败仍按既有退避/最多5次与拒绝后等待邀请策略收敛。车机邀请优先，手动停止的10分钟暂停及车型限制仍有效。
- **车机 Wi-Fi 中断恢复（实验）**：保留已有短窗口机制，规则如下。两项同时开启且存在有效中断凭证时，优先原有首次立即恢复；无凭证时由新开关授权已知网络路径，不把持续轮询当成新的首次恢复机会。

正常邀请和当前iAP2端点优先。设置里的「车机 Wi-Fi 中断恢复（实验）」默认关闭，沿用原主动连接开关的保存值。648起，该开关不再授权宝马首轮根据历史配对、热点、缓存端口主动建AirPlay。只有本进程已观察到由车机邀请/本轮经典iAP2发起的会话完成RECORD、资源应答、主屏SETUP、视频TCP、视频写帧及TCP确认，随后意外中断，才提供同车型/车机身份/热点的120秒恢复窗口。窗口内首次恢复在车机网络可用后立即尝试，不增加重连调度延时或10秒稳定等待；首次实际拨号才消耗这次快速机会。失败后的后续恢复保留10秒网络稳定等待及原退避，实际主动尝试最多5次，普通轮询不扣次数；真实邀请始终优先。主动会话自己的视频计数、重复失败及ACL波动不能生成资格、延长窗口或补次数。手动停止/启动/等待中手动重试、关闭自动连接、清身份、换车/换热点及进程重启均不能继承主动恢复资格。短时网络丢失后回到同一已绑定车机热点可以在原窗口内恢复，不能据时间窗口直接判断用户是否已经离车；仅开启中断恢复时，超时二次上车仍等待新邀请；独立主动连接开关开启时可按已知网络路径尝试。上述发送端事实仍不证明车机已显示桌面。

两项都关闭时只广播 `_carplay-ctrl._tcp` 并等待车机邀请。其它车型原有正常发现路径仍遵循自身档案，不以该实验开关绕过大众新鲜邀请或奔驰本轮参数要求。

已在等待邀请时，ACL 连上、退场和 companion 唤醒先检查 ctrl 广播是否仍属于当前 Network 与手机身份。健康注册持续保留，不因蓝牙短暂断开或定时轮询注销重播；仅网络、身份变化或注册确已失效时重建，避免制造发现空窗。进程绑定尚未完成时，只要本轮会话还在协商且手机已经连着已知车机 Wi-Fi，ACL 退场不拆会话。等待邀请期间首页手动连接可结束本轮并立刻新开一轮，不创建十分钟暂停。

控制连接或视频TCP前失败时，只回收失败引擎。连接失败及其它暂态失败按10/20/40/60秒退避，最后两次为60秒间隔，最多5次自动恢复，耗尽后等待新邀请；范围绑定Network和车机MAC。若无邀请、由手机自己拨出的 :7000 已获 RECORD 确认、却在初始资源确认前被车机拆掉，则本轮同一车机/网络既不做定时重放，也不把随后的 ACL 状态变化当成恢复机会，继续等车机发起 iAP2。有 ctrl 邀请或本轮已经有 iAP2 的激活关闭，仍允许有界恢复：失败后必须出现同车新的经典蓝牙 ACL 连接边沿，距失败至少 30 秒且最后一次连接/断开后安静 10 秒，最多恢复 2 次，并计入原有 5 次总重试预算。旧连接快照、重复广播、仅断开或单纯时间流逝均不提供机会；蓝牙波动和暂时失去资格不重置预算。暂停、主动开关关闭、身份/车型/绑定网络不满足时不尝试。这是保守兼容策略，不是宝马协议时限，也不直接检测NFC刷卡或钥匙权限；仅中断恢复模式还必须满足上述本次正常连接中断资格；新连接轮次/新网络本身不授权首次主动尝试，已知网络主动连接则需用户独立开启新开关。这是按阶段收敛恢复，不代表收到明确拒绝码。

媒体失败可暂用同范围仍可连接候选，控制端口失效则清除后重新发现。真实邀请或新iAP2端点可提前继续。未配对网络、开关关闭、车型禁用或其它车机占用时仍只等待邀请。

555–557“首次失败后整轮只等邀请”已被后续有界重试替代。大众仍要求当前网络20秒内ctrl邀请，奔驰禁用无本轮参数的主动捷径；这些不施加给BMW。详情见[档案](HEADUNIT-PROFILES.md)。

## iAP2 订阅与字段边界（563）

蓝牙与Wi-Fi共用认证后订阅应答器：通信、通话、列表、电源和应用发现的早到Start有界暂存，同族Stop撤销未发回复；明确识别拒绝立即结束，证书与签名仅做参数完整性检查，不宣称标准认证通过。蓝牙支持AA06序号到完整证书的一次跟进，保持原截止时间；Wi-Fi所有CSM按协商maxLength分片。

列表请求 `0x4170 → 0x4171` 按成功盒子固件的存在性映射：请求含参数 1 才回复 `u8(0,0)`，含参数 6 才回复 `u8(5,0)`；均未请求时回复空正文。不固定添加参数 2/7，不构造联系人或列表记录。认证前暂存、后续请求覆盖、Stop 撤销仍按原顺序执行。`IAP2-LIST` 只记录字段编号与长度，不记录值；收到回复不代表车机完成激活。

4301无线组按字段形态区分两种布局，SSID按UTF-8字节限长，密码不以IP或冒号作过滤；本轮新完整AP优先于旧缓存。SDK、mutualAuth与公钥形态仅作诊断，不改变设备标识/BSSID边界和AirPlay信任路径。无实际消费的车况请求不主动发送；导航合法订阅在关闭HUD时仍可收到无路线状态。

## BMW 盒子成功流程对照

MGU 成功日志的主线是：经典 iAP2 识别/认证 → 5702/5703 热点凭据 → 入网取地址 → Bonjour/ctrl 邀请 → pair-verify 与 AirPlay 会话 → 能力/资源/保活 → 主屏交接及视频。Wi-Fi iAP2 在会话阶段另做 Detect/SYN/识别/认证及状态订阅，与视频启动并行；5703 后没有 4301 不代表缺少邀请流程。

566 将宝马盒子兼容流程的 disableBluetooth 请求移至 RECORD/资源声明完成后、视频 SETUP 前，不再以 Wi-Fi iAP2 就绪为发送前提，避免交接互等。每轮只请求一次，最长等待 3 秒，失败继续协商；取消或代次失效则退出。此请求不关闭手机系统蓝牙，200 也不代表交接完成；确认可保留会话仍要求本轮 Wi-Fi iAP2 就绪且 feedback 健康。同时接收 event 与 control 两个入口的 iAPSendMessage，控制入口沿用 RTSP 应答，补上原先遗漏的业务转发；诊断仅记录入口、计数与字节数。宝马档案仍保留额外 EA 开启流程。

565 对齐列表回复 4171，并将通信回复 4158 收敛为只输出车机请求的已知单字节能力字段；未实现的电话能力保持 false，未知 SIM/运营商等状态不填造，空请求回复空正文。两类订阅都保留认证门槛、覆盖和 Stop 撤销，畸形请求不生成业务回复；诊断仅记录字段编号与长度。原始盒子 WLAN 日志多只保留报文头，字段结论应有固件分支佐证。此对照不等同于二次上车、暂停保网或已有 Wi-Fi 切换已验收。

## 停止、清除与退出

主动停止当前有效轮次会暂停自动连接10分钟；后续ACL/Wi-Fi事件不能绕过。用户明确手动启动/重试或重新开启自动连接时，会清除旧暂停记录、取消恢复定时器/闹钟并恢复网络监听，不把旧暂停带入新一轮失败回退。预检不通过的启动请求不会清除暂停。

607 起首页停止操作携带所显示的 connectionAttemptId，并在会话控制锁内再次核对轮次及状态；旧轮次、失败/结束后的迟到停止和重复停止不能创建或延长暂停。按钮按连接轮次与操作状态分组，启动→停止、协商→已连接等变化会取消旧按压，避免手指按下时的启动按钮在松开时变成停止。自动连接开关变更同样串行处理，排队的旧开关请求由最新请求失效。自动断链和建链失败不创建暂停。

自动关闭时释放监听及发现资源；自动待机可保留身份声明但不扫描、不拨号、不执行iAP2握手。

单车清除按明确MAC处理配对/凭据；全部清除是另一个高级操作。停止与系统解绑、删除身份不能混为一谈。媒体任务、网络租约、端点及UI生命周期按会话代次回收；正常退出先停媒体，再有界TEARDOWN，异常退出不伪造优雅成功，见[协议](PROTOCOL.md)。

## 设置与状态

首页自动连接快捷开关与设置使用同一持久值；会话连接时显示阶段卡片。深浅主题/跟随系统仅改变手机App，车机主题在车机设置。连接诊断见[阶段说明](HANDSHAKE-DIAGNOSTICS.md)。


## BOX-OFF 重连机制移植（610）

掉线后的会话级恢复采用2/5/10/30/60秒共五次预算。同一恢复链上的协商失败继续消耗预算，不因控制层connected清零；当前视频管线实际写帧后开始观察，维持约120秒后断开才重新补足预算。手动启动、关闭自动模式或换到另一车机可清除旧预算。耗尽后保留待机，不阻止真实车机入站；Wi-Fi能力变化通知不能绕过正在执行的退避或耗尽预算。首次从未建立链路的失败仍不直接启动掉线恢复链。

会话内已知Wi-Fi主动激活仍保留10/20/40/60/60秒间隔，但最多五次，不再无限重放；已确认的激活关闭仍优先等待新邀请。无邀请且由手机自己拨的 :7000 在 RECORD 后被拆时，不触发定时重放，也不触发 ACL 恢复。其余激活关闭仅允许上述新ACL证据触发最多两次有界恢复。该限制不禁止新Network、新车、手动新轮次的首次尝试，也不把所有已配对车机恢复成只等邀请。

入网前读取实时Wi-Fi句柄、SSID、有效本机地址、到车机的非默认路由；端点 deviceIdentifier 表示设备身份，不等同于热点 BSSID，不能要求二者相等。当前请求所有权、相同 SSID/凭据及实际 Network 归属均可作为复用证据；只有缓存 SSID/句柄不能授权复用。被ROM隐藏的BSSID可通过已授权Shizuku读取wifi status；不删除系统网络或修改配对身份。多Wi-Fi无法唯一匹配时不随意选择第一条，失败后也不回落到未经核实的网络。已有NetworkSpecifier请求若仍持有同一网络则保留。

终止清理、网络绑定及核心启动共用会话控制锁。失败回调先排队并核对轮次，作废socket租约、取消/等待旧连接，再释放本轮引擎/网络。旧FD未获当前轮次接管时立即关闭；旧协程finally不能清掉新轮次connecting。保留既有地图任务与导航状态，继续通过已有UI生命周期代次释放编码器及Surface；本版没有另启CarWith实例或新增视频重建实验。手动停止后的十分钟自动暂停与iPhone身份监听策略不变。


有网 Wi-Fi 切换到车机局域网时，读取已保存网络时按网络编号、SSID及autojoin状态精确去重，兼容ROM返回重复项；冲突项仍拒绝。若自有请求已激活、选择回调已就绪且约2秒仍未选中热点，允许一次有界扫描恢复：仅对当前不同于目标的已保存互联网 Wi-Fi 临时暂停自动加入并断开，随后请求扫描，最多8秒轮询新结果。重复请求、旧回调、已选中热点、当前已在目标热点或请求不属于本App时均不能触发；成功、取消或超时清理时恢复原自动加入设置。恢复缓存只接受本次恢复开始后的新扫描记录（缓存年龄不超过30秒），同名多AP且无精确提示时不任选一个。此路径不保存车机为系统默认互联网网络，实际入网仍以有效 Network 回调/核验为准。
