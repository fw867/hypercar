# 握手诊断与首次配对保护

## 日志怎么读

- `HS#编号 +毫秒`：同一条蓝牙 iAP2 会话，含入站/出站方向、目标模式、本机身份及本车凭证是否存在、iPhone 角色声明。
- `PHASE`：链路协商 → 识别 → MFi → EA/HID → Wi-Fi 凭据 → CarPlay 会话参数 → 保持链路，记录前一阶段耗时。
- `TX / RX`：消息 ID、长度、最大分片载荷和是否等待链路 ACK；新增摘要不输出密码、私钥、挑战或签名值。
- `WAIT / MATCH / TIMEOUT`：等待哪些消息、预算、是否命中早到暂存帧、实际耗时。
- `RTSP#编号 TXQ/RX/ERROR`：控制/事件 TCP 连接各自编号，带 CSeq、方法/路径、长度、是否加密、应答状态和耗时。成功的 feedback 心跳不逐条记录，错误仍记录。
- 关闭日志区分对端 EOF、读取失败、本地解密失败及未完成事务。不同 RTSP 编号表示换过连接，不能把它们的 CSeq 混在一起。

内存导出扩大为最近 1600 行；重启恢复上一进程末尾 400 行；磁盘仍有大小上限。链路帧每方向最多摘要 128 条，CSM 接收摘要最多 192 条，避免保活刷屏。复现后尽快导出，长时间反复重连仍会淘汰早期记录。

## 自动发现与指定目标

以前运行时使用 `用户指定 MAC ?: 缓存 ACL MAC` 同时作入站过滤。清除设置中的目标后，旧 ACL 地址仍在，导致界面显示自动、实际只接受旧设备。

现在入站只看用户明确指定的目标；自动模式不以 ACL 缓存限制来者。ACL 地址仅是出站优先候选。设置页的下拉、手动输入、清除与切车型全部走同一更新入口，同时清除旧候选并刷新界面。只取消尚在拨号的出站连接，不中断已经建立的 CarPlay 会话；已有会话不会因为选了自动发现而被强行切走。

## 用什么判断“首次”

必须区分三种本地证据：

1. 全局 `controller_identity.txt`：手机自己的长期身份，存在不代表配对过当前车机。
2. `controller_identity.txt.paired-bt_<车机蓝牙地址归一键>`：该车机的 AirPlay 注册/验证历史，跨热点 IP 变化保持稳定。
3. 设置里的“曾连接成功”列表：会话成功历史，不单独当作现存有效凭证。

没有本车记录按“首次或未知”处理，所有档案都不会因配置开关而主动断 HFP/A2DP。BMW 档案继续只监听，不做后台 SDP、出站拨号或配置文件断开。

有本车凭证时先尝试 pair-verify；车机已删除授权或验证失败，才切到新控制连接按既有流程重新配对。本地记录不能证明车机仍有授权。旧版只有 IP/公钥标记时，只有匹配到公钥，或同车蓝牙地址确有成功会话历史，才用于 verify 快路径；验证成功后写入稳定键。另一个车机复用同一 IP 不能因此被认作已经配对。

保留 iAP2 Device/iPhone 角色、`…cafe` SDP、`iPhone` 设备名、无线可用性与传输身份声明；不通过改变系统蓝牙名称或重新生成身份来掩盖连接问题。上述表示协议角色，并不意味着 Android 系统变成了真正的 iPhone。
