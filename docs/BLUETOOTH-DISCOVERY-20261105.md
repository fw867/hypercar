# 556：蓝牙接入诊断与主动发现完善

## 背景

555 配合 WinPlay 的五轮检测超时与一轮提前关闭中，电脑收到的蓝牙字节数均为零。系统记录显示 ACL 已连接且加密成功，但 iAP2 RFCOMM 直到重新建立 ACL 后才接入；手机主监听在此期间一直存在。此版本完善手机端边界诊断和已确认的发现缺陷。按用户选择，不修改 WinPlay。

## 蓝牙日志与交接保护

- `BT-ACCEPT`：主入口或标记入口拿到 socket 后、进入同步门控函数前记录，包含监听代次、对端、接入计数。可以识别系统已交付 socket、但处理函数尚未进入的情况。
- `BT-REJECT`：每个接入拒绝和迟到 worker 拒绝都有原因，包括旧代次、会话暂停、Wi-Fi handoff、非目标、重复连接和旧会话尚未退出。
- `BT-GATE` / `BT-HANDOFF`：状态变化附前后值、代次与调用原因。
- `BT-WORKER`：会话 worker 真正取得执行资格的时间与 ticket。
- `RFCOMM-IO`：首次 socket 写返回、首次读返回、结束时读写字节数与本地取消标记。不记录协议载荷；写返回不代表对端实际收到。
- `BT-HEALTH`：复用现有约 15 秒等待进度日志，记录监听注册、线程状态、门控、handoff、accept/reject 数量与最近接入/worker 时间，不增加轮询线程、不主动重建服务。
- 进入 Wi-Fi handoff 时使旧 ticket 失效；worker 发布 socket 与 handoff 状态切换使用同一把锁，防止旧任务在暂停后迟到启动。

若持续 `accepted=0`，需结合系统蓝牙记录调查接入上游；若出现 `BT-ACCEPT` 后紧接 `BT-REJECT`，可直接按原因定位 App 门控。仅有 SDP registered 不再被当作握手成功。

## 主动发现

- 将地址规划与并发探测分别提取为 `AirplaySubnetPlan`、`AirplaySubnetProbe`，便于验证实际失败场景。
- 修正 ARP 空白列解析，只接受完整邻居、正确网卡、本网段地址，排除手机自身、网络地址及广播地址。读取不可用时明确记录，并继续有界枚举。
- 修正 /24 未实际覆盖却跳过扩展扫描的问题；支持 /16 到 /30，保留原有 8192 个扩展地址上限。
- 常见地址和扩展地址都探测车机档案配置的全部候选端口；能够覆盖 `.38:17000` 等非常见 WinPlay 端点。
- 每个探测 socket 显式绑定选中的 Android Network。连接等待有界；换网、停止、新连接尝试、ctrl 邀请或新 iAP2 端点到达时停止继续扫描。
- 收到正常邀请时丢弃同时命中的扫描候选，邀请流程优先。保留主动失败后等待新邀请的逻辑及 10 秒稳定延时。
- `DISCOVERY` / `DISCOVERY-PROBE` 记录地址范围、候选端口、ARP 可用性、实际 socket 次数、网络绑定失败次数、中止状态和耗时。端口可达仍只表示候选，必须完成后续配对与会话激活。

## 验证与限制

- 207 项 JVM 单元测试通过，新增真实案例覆盖 /24 的 `.38:17000`、ARP 空格/制表符与网卡过滤、宝马 /20、较小前缀、扫描收到邀请时丢弃竞争命中、换网前不探测、handoff 后旧 ticket 不复活。
- Debug lint 无错误，47 条 Warning、2 条 Information，与此前记录一致。
- 签名 release 0.1.0.556 已构建并覆盖安装到手机，启动成功。本次没有 Rust 改动。
- 尚未证明 Windows 服务发现/RFCOMM 超时的根因，也不保证发现端口后车机一定接受无邀请连接；下一轮连接可用新日志区分阶段。没有清理配对身份、修改 WinPlay 或通过重启蓝牙来掩盖问题。
