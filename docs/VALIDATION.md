## 2026-11-15 BMW ID6／NBT Evo 实验档案

参考 CarPToCarL 的[音频优先改动](https://github.com/jjuugk/CarPToCarL/commit/1cc4e9da1078a8388e3c0024bd41108116a1a95f)及[单次 RECORD 约束](https://github.com/jjuugk/CarPToCarL/commit/054976de28a704a4f1965152b6d8ba4f62c4f3cb)，新增独立 BMW ID6／NBT Evo 档案；默认不切换用户已有选择，不把 NBT 策略套到 MGU、IDC23 或其它档案。

- **建链顺序：** NBT Evo 身份校验后，资源声明、屏幕 TCP、声明内音频 SETUP、单次成功 RECORD，再允许视频发送。准备失败清理屏幕且不发 RECORD；RTSP 或业务拒绝不记录为激活成功，并发激活串行化；新控制连接有独立状态。
- **音频：** 按本轮 `/info` 的 media 输出格式选择 AAC-LC 44.1/48 kHz 或 PCM 48 kHz；不猜缺失能力。44.1 kHz 同时落实到编码器、跨块重采样、SETUP 与 RTP 样本时钟；接管后不重放旧缓存，资源归还仍按协商采样率重建编码器。退出按实际 PCM/AAC 流类型清理。
- **隔离：** 不继承 MGU 的 SAP 引导、EA、传输标识或主动拨号；ID6 与 ID9/MBUX 前置策略互斥，下发 schema 11 阻止旧缓存覆盖 ID6。实际 WinPlay/DiPlay 身份继续走软件接收端路径。
- **未完成：** [参考项目的 iDrive 旋钮适配](https://github.com/jjuugk/CarPToCarL/commit/bdcc390528774b7639a4f8de9576b3a8da4748f6)是独立输入功能，本轮未移植。ID6 首次音画、播放稳定性、主屏归还及二次上车仍待实车验证，保持未实测标记。

### 奔驰媒体兼容与连接名称修正

依据晚间566日志，新增仅由奔驰档案ID派生的 `mbux_media_compat`，软件接收端不启用。会话能力保留既有字段和顺序，仅撤回本端当前未实现的 HEVC／mainBuffered 提议，继续 H.264 和已实现的 UDP 音频；不重新启用旧 MBUX 屏幕前置／SAP 实验。媒体格式按本轮 type100/102 media 输出声明过滤，不把 type103 的 AAC44 能力用作 UDP 支持；MGU、ID9、ID6、大众、奥迪的能力和默认顺序保持不变。

## 2026-11-14 恢复已配对Wi-Fi主动建链入口（同批563）
