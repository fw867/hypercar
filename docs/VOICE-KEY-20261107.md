# 方向盘语音键：按画面来源路由

用户选择：CarWith 使用其内置语音，自绘 UI 使用手机默认助手。两条路径均使用手机麦克风；没有实现车机麦克风的 AirPlay 输入流协商与上行。

## 入口及按键状态

AirPlay 事件 `requestSiri.params.siriAction` 和 Consumer HID `0xCF` 进入同一状态机。仅接收已知动作 1/2/3（预热/按下/松开），预热不启动；无效、负数、超范围动作忽略。HID 同时新增语音释放边沿，不改变媒体键按下沿及触摸路径。

重复按下不重复唤醒；15 秒未释放视为旧按键状态失效。来源重建会清除状态，旧会话任务随引擎关闭取消。短按松开不立即结束识别，避免用户松手后说话被截断。CarWith 长按达到 1.5 秒时松开发 VR_STOP；该阈值参考下述项目的兼容性记录，并非协议固定值，需要在具体车机上复测。自绘 UI 的聆听结束由默认助手处理，不用松开强制关闭助手。

## CarWith

通过已有加密 CTRL 通道发送 `0x68008`，protobuf field 1 为 `0x21 VR_START` 或 `0x22 VR_STOP`。与触摸共享序列化写入，不跨线程直接写 socket。语音命令两秒过期，源未就绪时丢弃，重连清空控制队列，避免旧命令迟到后突然唤醒。

功能配置保留 CONTENT_ENCRYPTION=1，新增 VOICE_MIC=1（手机麦克风），相应 count 改为 2。证据为本地反编译的 CarLife `CommonParams`（VR_START=33、VR_STOP=34、硬键消息 425992）和 `FeatureConfigManager.VALUE_USE_MOBILE_MIC=1`，并参考 [CarPToCarL](https://github.com/jjuugk/CarPToCarL/tree/6346bf7b63b052b2764eb19f1495891bc833c152) 的语音键实现及 [按键时序记录](https://github.com/jjuugk/CarPToCarL/blob/6346bf7b63b052b2764eb19f1495891bc833c152/docs/carlife-voice-siri-20261104.md)。本项目 CarWith 真正响应及取音仍需测试，不能把排队或写入成功当作识别成功。

## 自绘 UI

JNI 回调交给后台 Shizuku 执行系统 KEYCODE_VOICE_ASSIST（219），由 Android 选择默认助手，不硬编码小爱包名。不使用 MediaKey 路由，也不会在 CarWith 失败时转而唤醒另一个助手。执行前重查当前连接标识，避免旧请求在会话结束后执行。

2026-11-07 对已连接手机执行同一系统语音键后，`dumpsys voiceinteraction` 报告活动服务已绑定、`mShown=true`。手机当前默认服务为小爱。该结果仅证明系统助手可被唤起；首次启用、锁屏限制、麦克风权限和是否在车机上显示界面由系统/助手决定。`cmd voiceinteraction show` 在该 ROM 被权限拒绝，故未采用。

增加语音预热/重复/释放/长按/超时/源重建/非法动作测试、HID 语音按下与释放测试及 CarWith 硬键帧和过期时间测试。既有音频资源、媒体键、触摸和七通道鉴权测试保留。新增 `VOICE-KEY` 日志区分输入动作、来源路由、命令排队、源未就绪、命令过期及手机助手启动请求。
